# Seashell → публикация VK: пошаговая инструкция

Документ описывает **полный проход**: API на своём HTTPS-домене, проверки безопасности, сборка фронта и выгрузка на **VK Hosting**, настройки в кабинете приложения и типичные проблемы.

Репозиторий на Windows у тебя может лежать, например, в `seashell_vk\seashell` — ниже каталог приложения именуем **`seashell`** (где лежит `package.json` с `vite`).

---

## Часть 0. Что должно быть заранее

1. **Мини-приложение создано ВКонтакте** (например через [dev.vk.ru](https://dev.vk.ru) или управление приложениями). Запиши **`App ID`** (в проекте он уже указан в `vk-hosting-config.json` как `app_id` — если другой приложение в кабинете, впиши актуальный).
2. У тебя есть **сервер** (VPS/Beget/другой хостинг), куда ты можешь поставить **Node.js**, **PostgreSQL** и желательно **Nginx + HTTPS** (сертификат Let's Encrypt или тот, что даёт хостинг).
3. На компьютере для сборки установлен **Node.js** (версии как подходят текущим зависимостям проекта) и есть **npm**.

---

## Часть 1. Получить данные в кабинете VK

### 1.1. Защищённый ключ приложения (**`VK_APP_SECRET`**)

Это нужен бэкенду, чтобы верифицировать `vk_sign` в launch params и **не доверять** подстановке любого «чужого» `vk_user_id` заголовком.

1. Открой [dev.vk.ru](https://dev.vk.ru) → свои приложения → выбери мини-приложение Seashell (или нужный id из `vk-hosting-config.json`).
2. Раздел **«Настройки» / «Общие»** или **«Работа с API»** — найди **`Защищённый ключ`** (может называться «Секретный ключ приложения»).
3. Скопируй значение целиком.  
4. Никому не отправляй в открытый чат и **не коммить в Git** — только в свой `server/.env` на проде или в секрет-хранилище хостинга.

### 1.2. Токен для загрузки на VK Hosting (**`MINI_APPS_ACCESS_TOKEN`**)

Нужен для команды **`npm run deploy`** (CLI `vk-miniapps-deploy`), чтобы залить папку `build` как статический хостинг мини-приложения.

1. В том же приложении найди возможность выпустить **сервисный токен** с правами загрузки/управления мини-приложением (название в интерфейсе может отличаться между версиями dev-портала).
2. Создай токен с нужным сроком и скопируй его.
3. Для сборки локально сохраняй только в **`seashell/.env`** (файл **не попадает в Git** если он в `.gitignore`) или задай переменную окружения в CI.

Если утилита при первом деплое откроет браузер / запросит токен — следуй её подсказкам; итог — токен есть в конфигурации утилиты.

### 1.3. Иконки для модерации (отдельно от `logo.svg`)

В интерфейсе настройки приложения часто нужна **PNG-иконка**, часто указан формат типа **278×278** пикселей.

1. Открой `seashell/public/logo.svg` в редакторе или импорт в Figma/Inkscape.
2. Экспортируй **PNG 278×278** (можно добавить паддинги, чтобы символ по центру).
3. Положи файл у себя; при подаче/настройках в кабинете VK загрузи его в поле иконки.

## Часть 2. База PostgreSQL на сервере

### 2.1. Создать БД и пользователя

Подставь свои имена и пароли (ниже только пример).

```sql
CREATE USER seashell WITH PASSWORD 'СЛОЖНЫЙ_ПАРОЛЬ';
CREATE DATABASE seashell OWNER seashell;
```

### 2.2. Строка подключения **`DATABASE_URL`**

Формат:

```env
postgresql://ЛОГИН:ПАРОЛЬ@ХОССТ:5432/ИМЯ_БД
```

На том же VPS хост может быть **`127.0.0.1`**, если приложение Node и Postgres на одной машине.

Миграции/инициализация схемы: в проекте таблицы поднимает **`npm run api`** после подключения (смотри **`server/db.js`** / доку создания при первом старте) — главное чтобы **`DATABASE_URL`** был верным и приложение один раз успешно стартовало.

## Часть 3. API-сервер (Node / Express)

### 3.1. Какие файлы с окружением читает сервер

По **`server/load-env.js`** загружаются:

1. `seashell/.env`
2. `seashell/server/.env` (если ключи совпадают — **перекрывает** корневой)

На продакшене удобно держать секреты **только** в **`seashell/server/.env`** (или переменными окружения панели хостинга).

### 3.2. Создай `server/.env` на сервере по образцу

Скопируй с машины разработки шаблон **без секретов**:

- Локально: из репозитория файл **`seashell/server/.env.example`**
- Переименуй/отредактируй в **`server/.env`** там, где будет крутиться Node.

Минимум для продакшена:

| Переменная | Зачем |
|------------|--------|
| **`NODE_ENV=production`** | Строже поведение (CORS без списка = блок; TLS к GigaChat и т.д.) |
| **`DATABASE_URL`** | PostgreSQL |
| **`GIGACHAT_API_KEY`** | Доступ к GigaChat |
| **`VK_APP_SECRET`** | Проверка подписи; без него в prod в логе будет предупреждение |
| **`CORS_ORIGINS`** | Список `Origin`, с которых браузеру разрешены запросы к API |

Пример **`CORS_ORIGINS`** (одна строка, без пробелов после запятой):

```env
CORS_ORIGINS=https://vk.com,https://m.vk.com,https://web.vk.com
```

Если запрос идёт с **`vk.ru`** / **`m.vk.ru`**, добавь их так же через запятую.

### 3.3. Ставим зависимости и пробуем локально на сервере (опционально)

На сервере в каталоге с кодом:

```bash
cd seashell
npm ci
npm run api
```

Убедись, что процесс слушает порт (**по умолчанию `3001`**, задаётся **`PORT`**). Проверка:

```bash
curl -s http://127.0.0.1:3001/api/health
```

Ожидание: JSON с **`"ok":true`**.

На продакшене **снаружи** должен открываться **только HTTPS** через прокси; сам Node может висеть за Nginx на `127.0.0.1:3001`.

### 3.4. systemd (пример) — чтобы API переживало перезагрузку

Подставь пути под свой сервер (пользователь `www-data`, путь `/var/www/seashell` к примеру).

Файл `/etc/systemd/system/seashell-api.service`:

```ini
[Unit]
Description=Seashell API
After=network.target postgresql.service

[Service]
Type=simple
User=WWW_USER
WorkingDirectory=/ПУТЬ/К/seashell
EnvironmentFile=/ПУТЬ/К/seashell/server/.env
ExecStart=/usr/bin/node server/index.js
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

Дальше:

```bash
sudo systemctl daemon-reload
sudo systemctl enable seashell-api
sudo systemctl start seashell-api
sudo systemctl status seashell-api
```

(Если `node` ставился через `nvm`, в `ExecStart` укажи полный путь к бинарнику node.)

## Часть 4. HTTPS и прокси (Nginx пример)

Предполагается домен типа **`api.example.com`** → твой сервер.

### 4.1. Что должен делать прокси

- Терминировать TLS (сертификат).
- Проксировать **`/`** (или только **`/api`**) на **`http://127.0.0.1:3001`**.

Убедись, что заголовки запроса фронта доходят до Node: достаточно стандартного `proxy_pass`. Если используешь только путь `/api`:

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:3001;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Проверка с машины:

```bash
curl -s https://api.example.com/api/health
```

### 4.2. Какой URL писать во фронт

База для фронта — **тот же хост**, куда ходит браузер по HTTPS. Клиент в коде сам добавляет суффикс **`/api`** (см. `dictionaryApi.js`), поэтому во фронте достаточно:

- `https://api.example.com` **или**
- уже с суффиксом `https://api.example.com/api` (оба варианта поддерживаются).

## Часть 5. Сборка фронта (`VITE_API_URL`)

Сборку делай на **своём ПК или в CI**, заранее с правильными переменными **`VITE_API_URL`** (они «вшиваются» при **`npm run build`**).

### 5.1. Файл `seashell/.env.production`

1. Скопируй **`seashell/.env.production.example`** → **`seashell/.env.production`** в каталоге `seashell` (рядом с `vite.config.js`).
2. Открой и замени заглушку на свой домен API, например:

```env
VITE_API_URL=https://api.example.com
```

Файл **`.env.production`** попадает под игнор в Git по правилу `.env.*` — это норма, секрет там обычно не нужен, но URL не нужно утекать в репозиторий без необходимости.

### 5.2. Команда сборки

```bash
cd seashell
npm ci
npm run build
```

Появится папка **`seashell/build/`** — это то, что заливается на VK Hosting.

При ошибках с API после выкладки убедись, что ты **пересобрал** фронт **после** правки `VITE_API_URL`.

## Часть 6. Выгрузка статики на VK Hosting

Из каталога **`seashell`** после успешной сборки:

### 6.1. Токен

Убедись, что переменная окружения или запись утилиты содержит **`MINI_APPS_ACCESS_TOKEN`** (см. часть 1.2).

В PowerShell перед командой можно так (пример):

```powershell
cd C:\путь\к\seashell_vk\seashell
$env:MINI_APPS_ACCESS_TOKEN="вставь_токен_сюда"
npm run deploy
```

Не комить токен в репозиторий.

### 6.2. Проверка `vk-hosting-config.json`

- **`static_path`**: **`build`** (папка после Vite).
- **`app_id`**: id твоего мини-приложения как в кабинете.

### 6.3. Команда

```bash
npm run deploy
```

В логах должно быть сообщение об успешной загрузке. Если спросят подтверждение приложения или токен — следуй тексту CLI.

После успеха фронт мини-приложения доступен через хостинг ВК как положено в настройках типа приложения.

## Часть 7. Настройки мини-приложения на dev.vk.ru

Точный вид меню со временем меняют, но нужно последовательно проверить:

1. Приложение **ассоциировано** с нужным статическим билдом (часть это уже сделает `vk-miniapps-deploy`).
2. **Платформы**: мобильный клиент VK, при необходимости mvk / web — как планируешь публиковать.
3. Описание, категория, скриншоты — по требованиям модерации.
4. Ссылка на **политику конфиденциальности** — если форма модерации требует.
5. Загрузка **иконки** (PNG из части 1.3).

---

## Часть 8. Проверка «всё ли сошлось»

1. Открой мини-приложение из VK на телефоне/в браузере.
2. Открой **«Словарь»**, попробуй загрузить список слов / добавить слово.
3. Если запросы падают:
   - В десктопе: вкладка **Network** для запроса к API → посмотреть **`Origin`** и код ответа.
   - **401** или текст про **`Invalid VK launch params`** — проверь **`VK_APP_SECRET`**, заголовки **`X-VK-Launch-Params`** при полноценном запуске из VK (не из голого браузера без параметров запуска).
   - Ошибки **CORS** — добавить точный домен **`Origin`** в **`CORS_ORIGINS`** через запятую, перезапустить Node.
   - **502** или таймаут — GigaChat, сеть или прокси; смотреть журнал процесса `seashell-api`.

## Краткий чеклист

- [ ] PostgreSQL есть, **`DATABASE_URL`** верный.
- [ ] **`server/.env`**: `NODE_ENV=production`, `VK_APP_SECRET`, `CORS_ORIGINS`, GigaChat, порт.
- [ ] API снаружи отвечает **`GET /api/health`** по HTTPS.
- [ ] **`seashell/.env.production`** с **`VITE_API_URL`**, выполнен **`npm run build`**.
- [ ] **`npm run deploy`** с токеном среды.
- [ ] В кабинете VK: иконка, описание, политика (если нужно), платформы.

Если застрял на конкретном шаге — выпиши **номер шага**, **команда/скрин текста ошибки** (без секретов), и можно разобрать точечно.
